## Accomplishments

- Confirmed via direct code read that `xlsx_ledger.py::write_xlsx_rows_atomic`'s `except Exception` (not `except BaseException`) really did skip orphan-file cleanup on `KeyboardInterrupt`/`SystemExit` -- widened it to match `model_ledger.py`'s already-correct clause.
- Added a shared, age-gated `_sweep_orphaned_temp_files(directory, pattern, min_age_seconds=7200.0)` helper in `xlsx_ledger.py`, wired into both `write_xlsx_rows_atomic` and `model_ledger.py::_write_predictions_atomic` -- this is the part that actually self-heals the dominant leak mechanism (a hard worker-timeout kill via `run_supervisor.py`'s `taskkill /F /T` / `proc.kill()`, or an OS crash), which no in-process exception handler can ever intercept.
- Removed the second confirmed-corrupt orphan found live during this investigation, `data/sports/cs2/picks-39cd77nx.xlsx` (3772 bytes, `zipfile.BadZipFile`-confirmed, gitignored/untracked, nearly identical size to the previously-removed `data/main/picks-js40dfcf.xlsx` at 3770 bytes).

## Decisions Made

- Shared helper lives in `xlsx_ledger.py`, imported into `model_ledger.py` the same way `_replace_with_retry` already is, rather than duplicated.
