## Accomplishments
- Added `_event_utc_date(value: str | None) -> str | None` helper to `polymarket_scanner.py` that parses an ISO-8601 timestamp with `datetime.fromisoformat`, requires timezone-awareness, and returns `parsed.astimezone(UTC).date().isoformat()` -- fixing the bug where an offset-notation pick timestamp (`-0400`) and a Z-notation market timestamp for the identical real instant were misread as different calendar days by a raw `[:10]` string slice.
- `_lookup_model_prob` now hard-filters candidate picks to the exact same UTC calendar date as the query's `event_start_utc` before any team/selection matching happens, and returns `None` immediately if the market's own `event_start_utc` can't be parsed. A cross-date-only match (the stale-fallback bug) now fails closed instead of returning a wrong probability.
- Simplified the candidate tuple from `(score, created_at_utc, p_win)` to `(created_at_utc, p_win)` since the date-match scoring bonus is no longer needed -- every surviving candidate already passed the date filter, so the remaining ordering is the unchanged most-recently-created tie-break.
- Added 3 new regression tests (file went from 4 to 7 `test_` functions), confirmed RED before the fix and GREEN after.
- Deferred docs/ROADMAP.md item 5's close-out (see Deviations) into a dedicated `261112-2s6-deferred-items.md` deliverable with the exact replacement text ready to apply.
