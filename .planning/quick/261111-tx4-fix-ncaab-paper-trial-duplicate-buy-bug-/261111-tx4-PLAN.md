<objective>
Stop the NCAAB spread-v6 paper trial from buying the same game twice when the forecast re-mints a pick_id.

Purpose: on 2026-11-11 the trial paper-bought North Carolina Central @ VMI away +8.5 twice at 52¢ (order_ids `PAPER-NCAAB-V6-3f661234757843c9` at 17:48Z and `PAPER-NCAAB-V6-09543e74f6354902` at 21:11Z, event_id 203460). Planning-time inspection of the live ledger found a SECOND instance with the same cause: event_id 203509 home -8.5, pick_ids `0f76f199ae594b72` (17:48Z) and `25d7af5ec6cd4bef` (2026-11-12T00:13Z). Both happened because `run_ncaab_spread_paper_trial()` dedups only on pick_id (`_recorded_paper_pick_ids` ~L155-166 and the `seen` set ~L198-208), and pick_id is not a stable identity across re-forecast cycles. The fix uses the same game identity the live buyer already uses (`AutoPolymarketBuyer._build_bought_index` / `_is_already_bought` in auto_executor.py) in the paper trial's pre-filter only.

Output: a composite-key dedup in `src/model_prediction/portfolio/ncaab_paper_trial.py`, four regression tests in `tests/test_ncaab_auto_buyer_paper_trial.py`, and a revert check showing the tests catch the bug. The fix only prevents future duplicates. The two duplicate pairs already in the ledger stay as they are; cleaning them up is a separate operator decision.
</objective>
