**Code, parameters and serving match; one harness input differs; the retune survives it.**

- **The post-retune positive bias is early-season compression, not HCA.** Slope of actual on v6 (D1 non-neutral): 1.62 (Nov-2025), 1.43 (Dec-Feb), 1.17 (Mar), 1.61 on the 2026-11 holdout, intercepts -2.0, -1.9, -0.4, -0.9. I could not reproduce the quoted +4.3 / +1.9 / +0.2 (different cut; those rows were not available to me).

## Deviations from Plan

1. **[Split]** The holdout's 2025-26 tail is the ablation boundary: 85 games from 15 of 119 graded 2025-26 dates (12.6%), not the plan's last 20% (about 24 dates), because the ablation's 60/20/20 fractions run over all graded dates including 2026-27. The holdout had already been read, so I disclosed rather than re-split.
2. **[Reuse]** `validation.py::build_walk_forward_rows` / `chronological_split` were not used: they operate on `ValidationRow` objects that carry the learned-model feature vector. The ablation's `load_games`, `graded_days`, `summarise_spread` and `summarise_total` are the loader and scorers for this NCAAB model and were reused instead.
3. **[Fit window]** Coefficients were fitted on warm (Nov-2025) + train, not train only, with validation as a non-degradation check (as in v6 ablation round 2). Warm is the only early-season data before the holdout; validation is mature-season only.
4. **[Rule 1 - Bug, found after the single holdout look]** The ridge fallback counted only current-season games, so carryover was off on 2026-11-01/02 (121 of 150 sample-0 D1 holdout games). Fixed in `ncaab_v7_shadow.py` (commit `5e3b91ca`), regression test `test_carryover_is_active_on_the_season_opener` fails without the fix. A rebuild confirmed dev rows and the frozen coefficients are unchanged; the as-frozen run remains the primary result and the rerun is labelled post-freeze (`ncaab_v7_final_postfix.json`).
5. **[Replay correction, same commit]** My first replay numbers used the wrong line sign for home picks and compared against `p_fixed` from an older artifact. Corrected (line is the selected side's own spread; like-for-like current-v6 column); the first version's market-relative claim was wrong and has been replaced.
6. **Process:** `pre-commit` stashes and restores unstaged files during each commit; the shared tree was restored intact every time. The v6 holdout was not pristine (the plan's evidence and an earlier agent covered all games; I printed v6 holdout bias and daily bias while exploring); no v7 choice used a holdout number. I did not update STATE.md / ROADMAP.md (three executors write there in parallel); the orchestrator should record this task.
