<objective>
Stop the dashboard cache warmer from hanging process exit, and stop it leaking out of the test suite.

Two defects, both verified by the operator on 2026-11-22:
1. tests/test_dashboard_server.py::test_main_stops_cleanly_on_keyboard_interrupt runs the real
   dashboard_server.main(). Before the mocked serve_forever raises, main() lowers the pytest process
   priority, sets _SWR["on"], loads the live dashboard/cache_snapshot.pkl into _CACHE, hydrates the
   live jobs.json into _JOBS, logs to the live dashboard/server.log, and starts a real forever warmer
   thread. That thread outlives the test, rebuilds under later tests' monkeypatches (the live server.log
   holds their ValueError/TypeError lines), and overwrites the live snapshot.
2. _warm_caches(forever=True) runs its 7 never-returning warm loops inside a ThreadPoolExecutor.
   concurrent.futures registers an atexit hook (threading._register_atexit) that joins every executor
   worker at interpreter shutdown, so any process that started the forever warmer never exits: the
   pytest run above prints "1 passed in 2.63s" and then hangs, and the real dashboard hangs the same
   way whenever main() returns (Ctrl-C, a serve_forever error). While hung, builders that use their own
   executors log RuntimeError('cannot schedule new futures after interpreter shutdown') every 30 s
   (13,701 such lines in server.log since 2026-10-07).

Purpose: a dashboard that exits when told to, and a test suite that cannot touch the live dashboard
files or carry server-mode state between tests.
Output: test isolation (one test plus a minimal autouse conftest guard), a subprocess regression test
proven red-then-green, and an additive forever-branch fix in dashboard_server.py. No change to the
one-pass warmer, cache semantics, models, pricing, orders, or schedules. The live dashboard (PID 5340)
is NOT restarted; it picks the fix up at its next natural restart.

Task order is load-bearing: test isolation (Task 1) lands before any pytest run that includes
test_main_stops_cleanly_on_keyboard_interrupt, because running that test unmodified writes the live
files and hangs the session.

Tracer-first does not apply: this is a two-defect fix with an ordering mandated by safety (isolation
before any run of the leaking test), not a layered feature with a path to prove end to end. Repo
precedent: quick-261122-mjo.
</objective>
