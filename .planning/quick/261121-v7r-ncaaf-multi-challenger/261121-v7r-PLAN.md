# quick-261121-v7r: more than one challenger per sport/market; route cfb-structural-v7 beside v6.2

## Goal

cfb-structural-v7 makes Flat/research paper picks next to cfb-structural-v6.2. Unchanged: champion v5, its
routing, Main behaviour, the auto-buyer whitelist (v5 only), and every v6.2 Flat pick (operator rule: nothing
is taken off production; v6.2 is not displaced).

## Design

1. Schema (config v3, backward compatible): `challengers.<SPORT>.<market>` may be a model id (as today), a
   list of ids, or null. The first listed id is the PRIMARY: the lifecycle contract's `challenger_model_id`,
   `registry.challenger()`, qualification. `CHALLENGER_METADATA_KEYS` (`prospective_challenger`,
   `research_candidates`, which MLB already carries as a list) are never routes.
2. Registry: `_resolve_challenger_routes` validates each configured id on its own (registered, available,
   sport/market contract covers the route, not the champion, not listed twice, a string) and never raises;
   problems go to `registry.challenger_problems`. New `challengers_for(sport, market)` returns every healthy
   one in order. `challenger()` keeps its meaning (primary only, no fall-through to the next id), so v6.2's
   `routed_markets()` and the qualification registry behave as before. Contract construction no longer hashes
   a raw list (it raised TypeError on `chall_id in entries`).
3. Promotion: `remove_challenger_route` drops one id from a list (collapses to a scalar at one, deletes at
   none); `promote` and `reject_challenger` used `==`, which never matches a list, so a rejected list member
   would have kept picking.
4. Hook (`build_cfb_slate`): routes read from the registry; each routed challenger runs in its own
   try/except, v6.2 first with the same call and the same event dicts, then v7. `challenger_pricing` stays
   v6.2's summary; `challenger_pricing_by_model` holds every challenger's. `cfb_structural_v62.py` is not
   edited (it is in v6.2's code_revision). `_forecast_cfb_sport` is unchanged: versions outside v2-v5 already
   go to research + Flat only, the ledger duplicate key includes model_version, and NCAAF eligibility ignores
   exposure.
5. v7 routing module: v6.2's quote rules (captured `polymarket_us` book observed at or before the decision,
   max-edge side, emit only when edge > 0), own model id, artifact hash (checked against the registry entry)
   and code revision. Live data comes through ONE seam owned by quick-261121-v7l:
   `cfb_structural_v7.price_v7_slate(data_root, decision_time, games, *, model) -> (results, summary)`. Until it
   exists the slate no-calls (`NO_CALL_V7_LIVE_DATA_UNWIRED`) and writes nothing; seam no-calls are counted.
6. Slug hygiene: v7 rows record the real contract slug (moneyline unsuffixed) as `market_slug=<slug>` and
   no parenthesised token, so settlement, the pre-kickoff close and the ticket gate read the contract.
