## What changed

**Task 4, restore (root cause).** `cli/daily.py` cleared every not-yet-started open row (all leagues, no filter) before re-forecasting and never called `restore_unreplaced_picks`; only `run_forecast` did. Evidence: zero `op-restore-unreplaced-*` records in `ledger_events`. Of the 24 lost flat event-markets, 19 were superseded before restore existed (commit 15b7bb43, 2026-11-11 02:04Z), and the 5 moneylines (events 229958, 203480, 203484, 229978, 209173; 11-11..11-13) went through the unwired daily path. Capture and restore now live in shared helpers (`_open_ncaab_rows`, `_restore_unreplaced_ncaab` in `cli/commands.py`) used by both daily and `run_forecast`. Restore takes `exclude_slots` so a slot a gate declined is not reopened (4 of the 5 lost moneylines had negative saved edge, which the new moneyline gate declines). Nothing is restorable retroactively: those slots were retired mid-run in the past and their events have started; no ledger rows were touched.

**Task 1, flat gates** (`college_basketball_forward.py`):
- Divergence gate now applies to Flat (and so to every tier). It is measured in the model's away frame: the spread model's `mean` is the expected HOME margin, but the old Main gate compared it with the selected side's own line, whose sign flips for home picks (a home pick on a heavy favourite was gated wrongly, and large divergences on small home lines passed). Rule 1 fix, pinned by tests.
- Serving probability >= 80% caps stake at 1.0U on Flat and Main (`HIGH_PROBABILITY_STAKE_FLOOR`, `HIGH_PROBABILITY_UNIT_CAP`). Needed an opt-in `EligibilityResult.units_cap` honoured by the Flat and Main branches of `PickLedger.append_evaluated`, because that code recomputes units from edge and could lift a passed 1.0 to 2.0. Default None leaves every other sport untouched.
- Moneyline emits only with edge > 0.
- Same-slate same-direction totals capped at `MAX_SAME_DIRECTION_TOTALS_PER_SLATE = 8` per direction (override `models.NCAAB.max_same_direction_totals`, 0 disables); quoted picks then highest edge are kept. Limitation: the cap counts only the not-yet-started games in the current run, so later runs on the same date can add picks beyond 8.
- Declines are reported in `result["skipped"]` and `result["declined_slots"]`; they are not written as zero-unit rows (the counterfactual lives in the daily report only).

**Task 2, quote honesty.** `model_opinion_indicative_market` has not been written by NCAAB serving since 96d85261; the live class is `polymarket_us_indicative`. The rule shipped is the literal placeholder class: no executable quote AND slate price exactly 50% persists at 0 units with an `[UNQUOTED_SHADOW]` rationale marker (80 of 565 flat v6 rows since 11-11). The ledger's `enforce_universal_paper_call` forces positive units on research/gated rows, but those only receive quoted rows, so this does not reach them. The paper trial (`auto_buyer_ncaab_spread_paper_trial.json`, enabled) reads Flat and Main rows by saved edge and would still lift a 0-unit row to `min_shares`, so `eligible_trial_pick` now rejects rows with units <= 0. No change to `auto_buyer_state.json` or `auto_executor.py`: NCAAB models are in both blacklist layers and all three `disabled_sport_markets` entries, and the live bucket is disabled.

**Task 3, totals main line.** Slate `price_probability` is an ask/last trade (0.99 vs 0.26 pairs on one line) and untraded alternates sit at 0.50, so "closest to 50%" picked off-balance lines. Predictions already exist for every line, so after candidate evidence the main line is re-chosen from fresh (<= `max_quote_age_seconds`) two-sided BBO mids, accepted only when the best mid is within 10 points of 50%; otherwise the slate rule stands. The pick is priced from the chosen line's own quote; `main_line_source` (`bbo_mid` or `slate_price`) is recorded in the snapshot features. Totals only.

**Task 5, CLV.** Settlement derived its snapshot root from `Path(ledger_path(config)).parent` = `E:\MP\data`, while snapshots moved to the runtime root on 11-04, so the lookup never found anything: all 738 settled v6 rows (610 flat, 128 main) have empty `closing_*` and `probability_clv`. `_closing_probability_for_moneyline_pick` now reroutes only the legacy repo root through `rerouted_data_root` (isolated roots, so tests, untouched). Read-only check on live data: lookup finds a close for 370 of 610 settled flat rows; for 110 matched-quote rows, the same side mapping reproduces the recorded `executable_ask` in 107 and declines (blank, not wrong) in 3. Fields stay `""` (not None) when nothing is archived; settled rows are skipped on re-run, so it is idempotent. Closing data is accounting only, never a decision input.
