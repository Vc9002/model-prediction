# Phase quick-261112-112 Plan 01: Generalize the events.jsonl full-file-read fix Summary

Added `AuditLog.reversed_events()` -- a lazy, bounded, backward-chunked generator -- and rewired the two genuine remaining full-file-read anti-patterns in the audit-log-adjacent codepath (the dashboard's `/api/audit` tail and the real-money `single_order` double-buy guard) to use it, while confirming every other JSONL/log full-read in the codebase is a correct-by-design read (ingest-ordered max-scan, or a genuine read-modify-write merge) and leaving those untouched.

## What Was Built

**Task 1 -- `AuditLog.reversed_events()` (src/model_prediction/audit.py):**

A new generator method, placed directly after `events()` and before `append()`. It opens the audit log in binary mode, seeks to EOF, and reads backward in 65536-byte chunks (the same chunk size `append()`'s own previous-hash tail-read already uses), splitting the running buffer on newlines after each chunk, carrying forward a possibly-incomplete leading fragment to the next chunk, and yielding each complete line's parsed JSON in reverse (newest line within a batch first) as soon as it's available -- never materializing or parsing the whole file before the caller sees the first event. A line that fails to parse as JSON is skipped via `continue` rather than raised, matching both call sites' existing tolerance for a corrupted record.

It is deliberately standalone: it does not call into or refactor `append()`'s existing backward-chunk logic for the hash-chain's previous-hash lookup (lines 76-100 at HEAD before this plan) -- that logic is already fixed and already tested, and was explicitly out of scope.

Four new regression tests added to `tests/test_audit.py`:
- `test_reversed_events_yields_newest_first`
- `test_reversed_events_on_a_missing_file_yields_nothing`
- `test_reversed_events_is_a_generator_not_a_materialized_list` (`inspect.isgenerator(...)`)
- `test_reversed_events_matches_events_reversed_across_chunk_boundaries` (four events, with 10,000-char and 70,000-char payloads to force the backward read across more than one 65536-byte chunk; asserts `list(log.reversed_events()) == list(reversed(log.events()))`)

**Task 2 -- rewire both consumers:**

- `src/model_prediction/dashboard/orders.py::_audit_tail()`: no longer reads `events.jsonl` into a Python list of every line (a live copy on disk at planning time was 428MB / 241,991 lines). Now constructs `AuditLog(path)` (local import, following `dashboard/common.py`'s own precedent for this class) and collects at most 25 items from `reversed_events()` via a plain loop with an early break -- since `reversed_events()` already yields newest-first, no second reversal is needed (the old code's double-reverse is gone). `total_events` now comes from the existing `_count_lines()` helper (already used elsewhere in the package for exactly this cheap byte-counting purpose) instead of `len(lines)`.
- `src/model_prediction/data_sources/polymarket_execute.py`'s `single_order` policy check (inside `PolymarketExecutor.execute`, the real-money double-buy guard): the generator expression's source changed from `reversed(self.audit.events())` to `self.audit.reversed_events()` directly. Every predicate (`event_type`, `subject_id`, `payload.action`) and the surrounding `next(..., None)` are untouched -- only the iterable changed. Early-exit-on-first-match semantics are preserved exactly; the gate no longer has to parse and hold the entire `audit.jsonl` as a list before the backward scan can begin.
- New test in `tests/test_dashboard_server.py`: `test_audit_tail_streams_the_newest_events_without_reading_the_whole_file_into_memory` -- appends 30 events with distinct `pick-{n}` subject_ids via a real `AuditLog`, calls the real `dashboard_orders._audit_tail()` through `patch_dash("DATA", ...)`, and asserts `total_events == 30`, `len(tail) == 25`, the newest tail entry is `pick-29`, and the oldest collected tail entry is `pick-5` -- proving count and newest-first ordering end to end through the real function, not just through `reversed_events()` in isolation.
