# Quick Task 261112-2s5: Fail-closed Auto-Buyer Dedup Index Summary

**`AutoPolymarketBuyer._build_bought_index()` now raises `BoughtIndexUnavailableError` (aggregating every failed source) instead of silently returning a partial dedup index on any read error, closing the real-money double-buy risk.**

## Accomplishments
- Added module-level `BoughtIndexUnavailableError(RuntimeError)` to `auto_executor.py`, matching the file's existing `StateVersionConflictError` sibling pattern.
- Changed all 5 of `_build_bought_index()`'s previously-silent `except ...: pass` blocks (audit logs, dashboard `orders.json`, `polymarket_picks.xlsx`, live+paper `auto_buyer_ledger.jsonl`, live Polymarket account positions) to log a warning and append `(source_label, message)` to a local `failures` list, without broadening or narrowing any caught exception type.
- Added an aggregated `if failures: raise BoughtIndexUnavailableError(...)` check immediately before the function's `return {...}` statement, so a non-empty `failures` list can never let a partial index escape.
- Confirmed (by direct code read, not assumption) that no caller-side change is needed: `evaluate_and_execute()`, `run_auto_buyer_cycle()`, `auto_buyer_worker.py::main()`, and `cli/daily.py`'s step 12 all already propagate/catch this exception class correctly.
- Added 3 new regression tests proving: (1) a single unreadable source fails closed, (2) `evaluate_and_execute([])` propagates the failure before any pick is evaluated, (3) two simultaneous unreadable sources are aggregated into one error naming both.
- Ran the plan's own regression-test discipline check: temporarily disabled the new raise, confirmed all 3 new tests failed with `DID NOT RAISE`, then restored the fix and confirmed all 3 pass again.
