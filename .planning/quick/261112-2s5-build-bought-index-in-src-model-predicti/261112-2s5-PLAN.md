<objective>
Fix the live-money auto-buyer's dedup index so a read error on any one of its source ledgers blocks ALL buys for that cycle (fail-closed, across every sport), instead of silently continuing with an incomplete index that makes an already-bought position look unbought.

**Confirmed bug, from live code at planning time.** `AutoPolymarketBuyer._build_bought_index()` in `src/model_prediction/portfolio/auto_executor.py` builds the set/dict structures `_is_already_bought()` checks before every buy decision, by reading 5 sources: (1) the audit log(s), (2) `dashboard/orders.json`, (3) `polymarket_picks.xlsx`, (3b) the live and paper `auto_buyer_ledger.jsonl` files, and (4) the live Polymarket account-positions snapshot. Each of these 5 blocks currently wraps its read in a broad `except (...): pass` -- confirmed at these exact lines as of planning time (they will have drifted slightly from the 261112-0li audit's cited ~1291/1318/1336/1453, and may drift further before this task runs, given this working tree's many concurrent uncommitted sessions):
- Audit logs loop: `except OSError:` / `pass` at lines 1294-1295.
- Dashboard orders file: `except (json.JSONDecodeError, OSError):` / `pass` at lines 1321-1322.
- `polymarket_picks.xlsx`: `except (OSError, ValueError, KeyError, TypeError, RuntimeError):` / `pass` at lines 1339-1340.
- The `auto_ledger_files` loop (live + paper `auto_buyer_ledger.jsonl`, the single most load-bearing source -- it is the durable local record of every live/paper fill): `except (OSError, ValueError, KeyError, TypeError, RuntimeError):` / `pass` at lines 1456-1457.
- Live Polymarket account positions (only read when `execute_live=True`): `except (OSError, ValueError, KeyError, TypeError, ExecutionGateError, RuntimeError):` / `pass` at lines 1471-1472.

`_build_bought_index()` is called exactly once per cycle, at the top of `evaluate_and_execute()` (line ~1707), before the per-pick loop. Today, if any one of those 5 reads throws, that source's contribution to `bought_pick_ids` / `bought_market_sides` / `held_slugs` / etc. is just missing -- the function returns a smaller-than-true index as if nothing were wrong, so `_is_already_bought()` returns `False` for a position that really was already bought, and the live buyer re-buys it. This is the exact bug described in the task: "a transient read error on any one ledger file lets the live-money auto-buyer re-buy a position it already holds, since the dedup index just looks empty for that source."

**The fix:** every one of the 5 blocks keeps attempting its own read (so one failing source does not stop the others from being tried -- maximizing diagnostic value), but a failure is recorded (logged + appended to a `failures` list naming the source) instead of swallowed. After every source has been attempted, if `failures` is non-empty, `_build_bought_index()` raises a new `BoughtIndexUnavailableError(RuntimeError)` whose message lists every failed source, *before* returning anything -- so no caller can ever receive a partial/incomplete index. Because this is the only call site in the live/paper execution path, the raise propagates straight out of `evaluate_and_execute()` (no try/except wraps that call there) and out of `run_auto_buyer_cycle()` (no try/except wraps `buyer.evaluate_and_execute()` there either) -- which means literally zero picks are evaluated and zero orders (live or paper) are produced for the whole cycle, across every sport, exactly matching the operator's locked decision ("fail closed, all sports"). This mirrors an identical, already-proven pattern already in this exact file (`run_auto_buyer_cycle`'s pre-cycle reconciliation: `logger.warning(...)` then `raise RuntimeError("Live auto-buyer stopped: pre-cycle reconciliation failed") from exc`) and in the sibling module `ncaab_paper_trial.py::_recorded_paper_dedup_keys` (whose docstring states the identical principle: "a read failure must propagate instead of being swallowed into an empty index").

**Why this needs no changes outside auto_executor.py.** Both real callers of `run_auto_buyer_cycle()` already fail closed on a propagated `RuntimeError` with no code change required: `auto_buyer_worker.py::main()` catches `(OSError, ValueError, KeyError, TypeError, RuntimeError)`, records `{"status": "error", "reason": ...}`, and returns exit code 1 (a loud, non-zero process exit plus a printed JSON diagnostic -- this is the production path for the independent, decoupled worker). `cli/daily.py`'s step 12 catches a broad `except Exception:`, logs `logger.warning("Automated Polymarket buyer cycle failed", exc_info=True)` (full traceback), and marks `auto_buyer_result = {"status": "error"}` in its report. The dashboard's manual "run now" POST route (`/api/auto-buyer/run`) has no try/except around this exact call today -- but neither does it today around the existing pre-cycle-reconciliation `RuntimeError` raise, so this is a pre-existing gap unrelated to this fix, not a regression; it is also a human-triggered, real-time action (the operator pressing a button and immediately seeing it fail), not the silent-automatic-rebuy risk this task targets. Out of scope.

**Two functions that look related but are genuinely out of scope.** `_today_auto_buyer_totals()` and `_get_quarantined_underperforming_models()` are called earlier in `evaluate_and_execute()` (before `_build_bought_index()`) and also read `auto_buyer_ledger.jsonl`, but neither has the "silently swallow into an empty-looking index that feeds a buy decision" bug: the former has no try/except around its own `read_auto_buyer_ledger()` call at all (a read error there already propagates, just without this fix's clearer labelling), and the latter's own narrow `except OSError:` degrades to an empty quarantine dict (a different, lower-stakes concern -- a model that should have been auto-quarantined simply isn't, not a double-buy). Neither is touched by this plan.

Purpose: close the real-money double-buy risk the operator identified, without touching any file outside this exact bug (per CONTEXT: "scope your plan to touch ONLY the files this task's own investigation proves need changing").
Output: `auto_executor.py` changed (new exception class + the 5 except blocks + the aggregated raise); `tests/test_auto_polymarket_buyer.py` gets 3 new regression tests proving single-source, end-to-end, and multi-source-aggregation fail-closed behavior.
