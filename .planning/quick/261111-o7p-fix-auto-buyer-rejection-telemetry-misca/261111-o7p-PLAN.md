<objective>
Two additive hardening fixes to the Polymarket Auto-Buyer, found in a manual code review (no CONTEXT.md / RESEARCH.md for this quick task — the task_detail is the spec):

1. Rejection telemetry: stop overloading `rejected_not_whitelisted` with decision-qualification rejections (new dedicated counter `rejected_not_qualified_decision`), and make `whitelisted_count` count only picks that cleared every categorical gate (move its increment after the disabled-sport-market block).
2. State-file conflict detection: add a monotonic `_state_version` to `auto_buyer_state.json` and the NCAAB paper-trial settings file; every save re-reads the live version and raises `StateVersionConflictError` instead of silently clobbering a concurrent writer (dashboard, scheduled worker, manual edit).

Purpose: the rejection funnel is how the operator diagnoses why the buyer skipped picks — miscategorized counters make that diagnosis wrong. The silent clobber is a live-money safety bug: `run_auto_buyer_cycle` loads state at cycle start and saves its stale copy at cycle end, so an operator who disables the live buyer mid-cycle gets silently re-enabled.

Output: patched `auto_executor.py`, `ncaab_paper_trial.py`, `routes.py`, `daily.py`; new `tests/test_auto_buyer_state_versioning.py`; extended `tests/test_auto_polymarket_buyer.py`; updated `tests/test_dual_auto_buyer_dashboard.py`.

Discretion choices (documented, no locked decisions exist for this quick task):
- Counter name `rejected_not_qualified_decision`; error class `StateVersionConflictError(RuntimeError)` — RuntimeError so the existing `(OSError, RuntimeError, TypeError, ValueError)` route handlers already refuse it with 400.
- One shared helper `write_versioned_state_file` in `auto_executor.py` serves both state files (ncaab_paper_trial.py already imports from auto_executor, so no new coupling) — identical conflict semantics on both paths.
- Conflict rule is strictly "live version > version read" (not `!=`), because `load_auto_buyer_state` can seed from the repo copy when the runtime file is missing; a missing/older live file must not raise.
- `save_auto_buyer_state` always raises on conflict. `run_auto_buyer_cycle` alone catches it once and re-applies only the keys the cycle owns (`last_run`, `last_daily_date`) onto a fresh load — the operator's concurrent change wins, the cycle's telemetry is still recorded, and a cycle that may already have placed live orders is not turned into a failed job by a benign concurrent toggle. A second consecutive conflict propagates.
- `paper_trial_status()` is left unchanged (returns file content as-is); the save helper treats an absent key as version 0.
</objective>
