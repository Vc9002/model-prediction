# Phase quick-261112-111 Plan 01: Per-model XLSX mirror drift audit and exit-code fix Summary

Made `audit_ledger_pnl.py`'s dry run fail its exit code on the stranded-open-row and settlement-conflict drift it already computed but silently ignored, removed the corrupt stray temp file that was crashing the script's own tier scan, and recorded the investigated-and-rejected verdict on full XLSX-to-generated-on-demand conversion in `docs/LEDGER_ROUTING.md`.

## What Was Built

**Task 1 (commit `53751665`):** Added a pure helper `_report_exit_code(report: dict[str, Any]) -> int` to `scripts/audit_ledger_pnl.py`, placed directly before `main()`. It returns 1 when `sqlite_integrity.ok` is False, when `sqlite_repairs_rejected` is non-empty, when `model_repairs_planned_total > model_repairs_applied` (unresolved stranded-open model-ledger rows), or when `model_settlement_conflicts` is non-empty (conflicts are never auto-resolved) -- 0 otherwise. `main()` now derives its return value from this helper and prints a one-line stderr drift summary whenever the exit code is non-zero, naming the unresolved-repair and unresolved-conflict counts and pointing at the relevant JSON report fields.

Also removed `data/main/picks-js40dfcf.xlsx` -- confirmed via `zipfile.ZipFile(...)` raising `BadZipFile`, 3770 bytes, dated 2026-11-02 (ten days old, not a concurrent write), not referenced anywhere in the codebase (`grep -rn "picks-js40dfcf"` returns nothing), and not the real `data/main/*.xlsx` per-sport workbooks (which are untouched). This stray atomic-write temp file (leftover from `xlsx_ledger.py::write_xlsx_rows_atomic`'s `tempfile.mkstemp`) was crashing `_tier_ledgers()`'s glob scan with an uncaught `BadZipFile` before the script ever reached the model-ledger comparison it was meant to run.

Added 5 new tests to `tests/test_audit_ledger_pnl.py` (`test_report_exit_code_*`) exercising all five `_report_exit_code` branches directly against small constructed report dicts, matching the file's existing style of testing pure helpers in isolation without sqlite/xlsx fixtures.

**Task 2 (commit `cafbe94c`):** Added a new `## Per-model XLSX mirror audit (2026-11-12)` section to `docs/LEDGER_ROUTING.md` (inserted between the existing "Dedup identity audit" section and "The four ledgers" section), covering: why full conversion was rejected (schema-gap table for `OPERATOR_FIELDS` and the five `MODEL_FIELDS` with no canonical column, citing the 2026-08-02 operator directive quoted in `model_ledger.py`'s own docstring); the root cause of the observed drift (the three fail-soft `try/except Exception` hook call sites in `ledger.py` at `_append_record` :1007-1014, `settle` :1405-1412, `update_closing_data` :1923-1930 -- current line numbers, which had shifted ~30-40 lines from the plan's approximate planning-time numbers); a re-measured live open-row snapshot (4,133 total, matching the planning-time count exactly -- it had not materially changed); the fix shipped (Task 1's `_report_exit_code`, with the actual live verify-run numbers: exit code 1, 27 unresolved stranded-open rows, 8 unresolved settlement conflicts); and the three open follow-ups.

## Open Follow-ups (recorded in docs/LEDGER_ROUTING.md, not fixed by this task)

1. **`model_ledger.py`'s own lock has no in-process fast path.** `_acquire_exclusive_lock`/`_lock()` (model_ledger.py :55-67, :443-451) go straight to the OS-level `fcntl`/`msvcrt` lock with a 0.1s poll and a 30s timeout -- the same contention shape sibling quick task 261112-118 is currently adding a `threading.Lock` fast path for in `ledger.py`'s own lock. `model_ledger.py` is untouched by that sibling task and untouched here; same contention risk remains, candidate for a follow-up once 261112-118 lands.
2. **`xlsx_ledger.py::write_xlsx_rows_atomic` vs. `model_ledger.py::_write_predictions_atomic` exception-handling asymmetry, likely the cause of the leaked temp file this task removed.** `xlsx_ledger.py` (:133) catches `except Exception`, so a forced process kill (`KeyboardInterrupt`/`SystemExit`, which are `BaseException` but not `Exception`) between `workbook.save` and `_replace_with_retry` would skip the `os.unlink(temporary)` cleanup and leak a `picks-*.xlsx` temp file -- exactly the shape of `data/main/picks-js40dfcf.xlsx`. `model_ledger.py::_write_predictions_atomic` (:741) already catches `except BaseException` for the equivalent cleanup. Worth widening `xlsx_ledger.py` to match, left as a follow-up since that file sits in the same export call graph sibling task 261112-118 is actively hardening.
3. **A real generated-on-demand conversion remains possible later**, but requires an explicit operator decision on where `OPERATOR_FIELDS` (`operator_decision`, `operator_selected_model`, `operator_selected_market`, `operator_units`, `operator_timestamp`, `operator_note`) and the model-only evidentiary fields (`code_revision`, `model_uncertainty`, `input_availability`, `missing_inputs`, `source_lineage`) would live if the independent `ModelLedger` write path were ever removed. Not a quick-task default -- this is a scoped, deliberate design decision for a future task.
