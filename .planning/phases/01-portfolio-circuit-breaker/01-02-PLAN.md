<objective>
Make the tripped breaker visible to the operator and give them the one action that clears it, then close the second buy choke point.

Purpose: SAFETY-02's visibility half and ROADMAP criterion 2. Plan 01-01 makes the system stop trading; without this plan the operator would have to infer the halt from an empty order log. Also closes the dashboard BUY path (D-07), which does not route through `AutoPolymarketBuyer` and so is not covered by 01-01's gate.

Output: an `error`-level alert in `status()`, a GET status route and a token-guarded POST reset route, and a refusal on the buy branch of `submit_order()`. No new frontend (D-06) — the existing dashboard already renders `alerts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> dashboard POST | An HTTP caller can reach the reset route. The origin check, `X-Dashboard-Token` constant-time comparison, and `confirm: true` requirement are the only things between a request and resumed real-money trading. |
| browser -> dashboard GET | Read-only status, unauthenticated by existing convention. |
| operator -> open positions | A safety halt that also blocks exits changes a drawdown into a trap. |
