# Required Betting Strategy

The sports model operates without market prices.

It first determines the most likely winner:

```text
home probability
away probability
predicted winner
```

That winner is frozen.

The market layer then evaluates only team markets aligned with the predicted winner.

Example:

```text
Model:
Team A 60%
Team B 40%

Market:
Team A 70¢
Team B 30¢
```

Required result:

```text
Predicted winner: Team A
Decision: NO_BET
Units: 0
```

Do not recommend Team B merely because Team B appears underpriced.

For spreads:

- the team must equal the predicted winner;
- the probability must be the cover probability for that exact signed line;
- moneyline probability must never be reused as spread probability.

For totals:

- freeze `OVER` or `UNDER` from the sports-only joint score distribution;
- evaluate only the frozen side at the exact line;
- return `NO_BET` if the exact line has no model probability.

Zero units is the default valid result.

# Phase 2 — Finish the Storage Foundation

## Raw snapshots

Preserve content-addressed immutable raw storage, but add atomic writes.

Required flow:

```text
serialize canonical bytes
calculate SHA-256
write to temporary file
fsync if supported
atomically rename to final path
verify stored hash
persist snapshot metadata
```

A raw snapshot record must retain:

```text
source
source_record_id
observed_at_utc
effective_at_utc
ingested_at_utc
snapshot_hash
path
schema_version
HTTP status where applicable
request parameters hash
```

Do not rely only on the file name to preserve observation time.

## Normalized tables

Replace unconditional concatenation.

Every table must declare:

```python
TableContract(
    name=...,
    primary_key=[...],
    schema=...,
    conflict_policy=...,
)
```

Implement one shared normalized writer:

```python
write_normalized(
    sport,
    table,
    rows,
    contract,
)
```

Required behavior:

1. Identical primary key and identical content:
   - idempotent;
   - do not duplicate.

2. Same primary key with a later observation timestamp:
   - retain both when the table represents observations;
   - or replace the materialized-current view while preserving history.

3. Same immutable primary key with conflicting content:
   - fail closed;
   - create an audit event.

4. Writes must be atomic.

5. Rerunning a collector must not increase row count unless new information exists.

## Feature snapshots

Feature snapshots must be immutable and versioned by:

```text
sport
event_id
horizon
decision_time_utc
feature_schema_version
dataset_hash
```

Do not overwrite `early.parquet`, `mid.parquet`, or `late.parquet` without preserving historical versions or manifests.

## Market snapshots

Market observations must be append-only and keyed by:

```text
market_id
side_id
line
period
observed_at_utc
```

Repeated identical snapshots must be idempotent.

Acceptance tests:

```text
[ ] Raw writes are atomic
[ ] Identical raw writes are idempotent
[ ] Changed raw payload creates a new snapshot
[ ] Normalized rerun creates no duplicates
[ ] Conflicting immutable row fails closed
[ ] Feature snapshots are versioned
[ ] Market snapshots are append-only
[ ] Interrupted writes cannot create a valid artifact
```

# Phase 3 — Correct the Point-in-Time Framework

Replace the current shared as-of implementation with a correct backward grouped join.

Required semantics:

```text
observation entity keys match
observation timestamp <= decision timestamp
newest valid prior observation selected
future observations never selected
stale observations explicitly unavailable
```

Required Polars shape:

```python
decisions.sort(entity_keys + [decision_time_col]).join_asof(
    observations.sort(entity_keys + [observation_time_col]),
    left_on=decision_time_col,
    right_on=observation_time_col,
    by=entity_keys,
    strategy="backward",
    tolerance=max_age,
)
```

Do not use:

```text
strategy="nearest"
```

because it can select future observations.

Preserve observation columns using a consistent prefix.

Add hard assertions after every join.

Create:

```text
tests/rebuild/test_asof_joins.py
```

Cover:

- future observation excluded;
- newest prior observation selected;
- stale observation unavailable;
- same-day doubleheader;
- player trade;
- probable-starter revision;
- lineup revision;
- injury revision;
- forecast revision;
- timezone boundary;
- null observation timestamp;
- duplicate observation timestamp;
- historical correction publication time.

Acceptance:

```text
[ ] One shared PIT join exists
[ ] Every rebuilt feature builder uses it
[ ] No direct date-only join remains where timestamps exist
[ ] All PIT tests pass
```
